# Mokly xtask

`xtask` owns repository-local verification for the Mokly workspace. It is an
internal binary and is not published to npm or crates.io.

## Responsibilities

- Run the complete gate, `cargo xtask check`, and each selected suite. The
  [CI verification contract](../docs/protocol/ci-verification.md) owns the
  suite boundaries and the report evidence.
- Run the live dependency audit first. Baseline mode is the default and fails
  on new issues or audit errors. Strict mode serves release and dependency
  update checks.
- Build the `mokly` binary for the host target and write the TypeScript types
  that the model and sidecar crates generate. Compare their exact bytes with
  `check-generated-types`, also required by Repository and CI.
- Enforce the 300-line limit on every Rust file under `xtask/` and `crates/`.
- Enforce the limits on changed TypeScript and JavaScript files (300 lines)
  and changed protocol Markdown (250 lines, or the exact reviewed cap in
  `xtask/protocol-document-caps.json`) against the fetched `origin/main`.
- Ratchet JavaScript and TypeScript file length, protocol caps, and unused
  internal exports against the branch point. Ratchet public package exports
  against release tags.
- Keep local gate coverage equal to CI checks on the host platform. Every
  Native command has local coverage; `npm run build` covers the host build.
- Run explicit and automatic remote checks on seven Testboxes with complete
  shard evidence.
- Stop warmed boxes on success, failure, SIGINT, SIGTERM, and SIGHUP.

## What This Crate Does

### Commands

| Command                               | Effect                                                                                                                                 |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `cargo xtask check`                   | Runs the local suites in sequence, in one checkout. Native runs only when selected. `--suite <name>` runs one suite.                   |
| `cargo xtask executor`                | Prints the executor that `check` selects, without warming boxes or running suites.                                                     |
| `cargo xtask build-native`            | Builds the `mokly` binary for the host target.                                                                                         |
| `cargo xtask generate-types`          | Writes the TypeScript types that the model and sidecar crates generate.                                                                |
| `cargo xtask check-generated-types`   | Checks exact generated bytes and rejects missing, changed, or extra generated files. It writes no files and runs in Repository and CI. |
| `cargo xtask rust-file-length-lint`   | Audits every Rust file under `xtask/` and `crates/` against the 300-line limit.                                                        |
| `cargo xtask source-file-length-lint` | Audits the changed TypeScript, JavaScript, and protocol Markdown files against their limits. `--all` audits every scoped file.         |

Every subprocess starts at the workspace root, even when xtask starts in a
subdirectory. `npm run build` builds the host target too, with the shim, the
sidecar, and the viewer.
Remote program discovery uses the command runner's Node shim resolver. On
Windows it also finds native programs whose names omit the `.exe` suffix.
On Windows, both subprocess adapters select the `.cmd` shims for npm, npx,
Corepack, pnpm, and Yarn. Other executable names and explicit paths stay intact.
Arguments remain separate from the program name.

### Suites

| Suite      | Content                                                                                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repository | Every check of the [repository gate list](../docs/protocol/ci-verification-repository.md#repository-boundary), in the listed order.                                                                                                       |
| Viewer     | The TypeScript typecheck of every project, then every discovered Node test file under `tests/` and `packages/viewer/tests/`. The suite has no shard.                                                                                      |
| Browser    | Every Playwright spec against one `mokly serve` of the example catalogue per worker, with zero retries. `--shard INDEX/TOTAL` runs one whole-file partition. CI and remote runs use four shards; the local gate runs the suite unsharded. |
| Native     | Build the `mokly` binary once, check Rust formatting and Clippy, and run the Rust tests of every crate. Hosted CI runs `--suite native` on macOS and Windows runners.                                                                     |

A selected suite is partial verification. The unqualified command is the
complete gate. A local run stops at the first failed suite. A remote run
reports every failed suite. Rerun one failed suite with `--suite <name>`.
The complete local gate also runs `npm run test:delivery:prepared` after the
browser suite. It builds the example and checks portable design specs through
static HTTP and file URLs. Remote verification runs this command on a
separate seventh Testbox after building the source. Hosted CI has a separate
required static-delivery job.
The local gate gets native build coverage from Viewer and Rust checks from
Repository. It does not repeat them in Native. Hosted native jobs repeat that
coverage on their own operating systems and are required by `Required CI`.

Viewer and Browser build the binary and viewer bundle first through
`npm run build`, then call only the strict runners, which skip the build and
fail when the build output is missing. Native builds the host binary through
`cargo xtask build-native`. Each browser worker's Serve renders the example catalogue from its
sources into the render cache, and the tests read nothing back from the
repository. Every suite rejects skips and todos.

`--shard INDEX/TOTAL` is valid only with `browser`. It uses one-based
integers with `INDEX <= TOTAL`. An unknown suite, a malformed shard, or a
shard with another suite fails before any subprocess starts.

Hosted CI runs the Viewer and Browser suites on Node 22.15.0, and also on
Node 24 for a Release Please pull request, under the
[runtime profiles](../docs/protocol/ci-workflow.md#runtime-profiles).
`Required CI` validates the report aggregate under the
[report evidence rules](../docs/protocol/ci-verification.md#inventory-and-report-evidence).

### Concurrency

The [test concurrency contract](../docs/protocol/ci-suite-evidence.md#test-concurrency)
sets the limits. Node runs at most half of the available CPUs' worth of test
files at once, never fewer than two. Playwright uses one worker. Each
Playwright worker owns one example server on a free loopback port. The shim
uses `--base refs/mokly/browser-suite-no-base --no-watch --port 0 --sidecars 1`.
The shared example waits for unavailable Changes and one Git diagnostic. `MOKLY_UNIT_CONCURRENCY` replaces the
Node file limit and `MOKLY_PLAYWRIGHT_WORKERS` replaces the worker count. Each
accepts only a positive decimal integer.

### Length Audits And Ratchets

The Rust file-length auditor runs inside xtask with the same failure
semantics as the listed commands. It audits every Rust file under `xtask/`
and `crates/` on every run. There is no ratchet and no override.

The source and protocol auditor is an xtask-invoked Node command. It finds the
workspace root with Git and checks the files changed against the fetched
`origin/main`, plus working-tree and non-ignored untracked files. It covers
`.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.mts`, and `.cts` anywhere in
the repository and `docs/protocol/**/*.md`. Git-ignored untracked files are
the only exclusion. During an uncommitted merge it compares the resolved tree
with `origin/main`, so main-only additions are not false violations. Fetch
`origin/main` before you run it.

The [repository ratchet contract](../docs/protocol/verification-ratchets.md)
owns the exact scopes and exceptions. Length, protocol-cap, and
unused-internal-export analysis compare with `git merge-base HEAD origin/main`.
Module analysis covers the `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.mjs`, and
`.cjs` modules under the three source roots the contract names: the
`@mokly/mokly` package source, `packages/viewer/src/`, and `scripts/`. The
internal-export baseline in `unused-internal-exports.txt` is sorted and
shrink-only across the branch. Protocol caps scan `docs/protocol/**`
recursively except `fixtures/`. The public-package-export ratchet compares
each released package with its newest matching release tag reachable from
`HEAD`. Full history and tags are required; when a release tag is unavailable,
fetch it with `git fetch --tags origin` and retry.

### Dependency Audit

`--dependency-audit <baseline|strict>` defaults to `baseline`. It is valid
for the complete gate and the repository suite. An explicit flag with another
suite returns a typed error before any subprocess starts. Baseline mode calls
`npm run dependencies:check -- --baseline`. It audits every dependency
category of the lockfile against the live registry, prints issues already
present at the comparison commit as inherited notices, and fails on new
issues or audit errors. Strict mode calls `npm run dependencies:check`, which
fails on every uncovered finding and invalid exception record. Ordinary pull
requests and every push use baseline mode. Release Please pull requests,
dependency update pull requests, release publishing, and the scheduled `main`
audit use strict mode. A remote complete gate passes the same mode to the
repository command on its Testbox. The
[baseline audit contract](../docs/protocol/dependency-audit-baseline.md)
defines the comparison. Reviewed exceptions have exact dev-only paths,
inclusive UTC end dates, and a maximum 31-day window under the
[dependency security contract](../docs/protocol/dependency-security.md#reviewed-workspace-exceptions).

`npm run dependencies:check:rust` follows the npm audit in both modes. It
builds pinned `cargo-audit` 0.22.2 with the reviewed tool lockfile and audits `Cargo.lock` against the live
RustSec database with `.cargo/audit.toml`. Unexcepted vulnerabilities and audit
errors stop the suite. The configuration records the single dated exception
and its review conditions. The daily
audit and read-only release preparation run the same command, including when release
verification reuses CI evidence. npm exceptions do not cover Rust findings.

## Quick Start

```bash
cargo xtask check
cargo xtask check --dependency-audit strict
cargo xtask check --executor local
cargo xtask check --executor remote
cargo xtask executor
cargo xtask check --suite repository
cargo xtask check --suite viewer
cargo xtask check --suite native
cargo xtask check --suite browser
cargo xtask check --suite browser --shard 1/4
cargo xtask build-native
cargo xtask generate-types
cargo xtask check-generated-types
cargo xtask rust-file-length-lint
cargo xtask source-file-length-lint
cargo xtask source-file-length-lint --all
```

Remote checks need `blacksmith`, `rsync`, and `ssh` on `PATH`, and a pushed
ancestor in the local origin refs. Set `BLACKSMITH_ORG_TOKEN` for org-key
login. For targeted test runs during development, use the
[developer test commands](../docs/protocol/developer-test-commands.md).

## Development

`cargo xtask` builds its executable in `target/xtask/`. Inner workspace Cargo
commands use `target/`, and native artifact builds use `target/native/`.
These separate directories prevent workspace tests from replacing the running
xtask executable on Windows.

Run the crate tests directly when you change command orchestration:

```bash
cargo test -p xtask
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

The `*_adapter_tests.rs` files under `src/remote/_tests_/`,
`src/remote/clients/_tests_/`, and `src/remote/snapshot/_tests_/` test
operating-system boundaries with real shell children and temporary
directories. The base and snapshot adapter tests create real Git repositories
in temporary directories. They use readiness signals and expected-state
waits, and they never assert elapsed time, as the
[test timing contract](../docs/protocol/ci-test-timing.md) requires. Fixture
Git setup and inspection use
[`git_test_runner.rs`](./src/remote/_tests_/git_test_runner.rs) with an empty
global config file and system config disabled. Code under test uses
`SystemProcess` with its real config, and captured requests record only that
code.

### Key Code

- [`src/artifacts.rs`](./src/artifacts.rs) owns native package builds,
  generated TypeScript, and the standalone generated-byte check.
- [`src/cli.rs`](./src/cli.rs) parses and dispatches commands.
  [`src/application.rs`](./src/application.rs) selects the effective
  executor, and [`src/executor.rs`](./src/executor.rs) parses executor modes
  and flag precedence.
- [`src/check/request.rs`](./src/check/request.rs) validates suite, shard,
  and dependency audit selections before subprocesses start.
  [`src/check/commands.rs`](./src/check/commands.rs) defines the shared suite
  commands, and [`src/check/runner.rs`](./src/check/runner.rs) runs them
  through injected process and file auditors.
- [`src/rust_file_length.rs`](./src/rust_file_length.rs) is the Rust
  file-length auditor. [`src/command.rs`](./src/command.rs) defines the
  injected command-runner boundary, and
  [`src/child_environment.rs`](./src/child_environment.rs) defines the secret
  and Git repository variable lists that every child drops.
- The [remote verification reference](./remote/README.md#key-code) lists the
  executor, snapshot, cleanup, and report entry points.
- [`../scripts/verification/source-file-length.mjs`](../scripts/verification/source-file-length.mjs)
  is the changed-file source and protocol length audit, and
  [`concurrency.mjs`](../scripts/verification/concurrency.mjs) owns the test
  concurrency limits.
- [`../scripts/verification/repository-ratchets.mjs`](../scripts/verification/repository-ratchets.mjs)
  dispatches the repository ratchets;
  [`ratchets/git.mjs`](../scripts/verification/ratchets/git.mjs) owns their
  merge-base workspace and reachable release-tag views; and
  [`typescript-length.mjs`](../scripts/verification/ratchets/typescript-length.mjs),
  [`protocol-caps.mjs`](../scripts/verification/ratchets/protocol-caps.mjs),
  [`internal-exports.mjs`](../scripts/verification/ratchets/internal-exports.mjs),
  and
  [`public-exports.mjs`](../scripts/verification/ratchets/public-exports.mjs)
  own the four ratchet policies.
  [`unused-internal-exports.txt`](./unused-internal-exports.txt) is the sorted
  shrink-only exception baseline, and
  [`protocol-document-caps.json`](./protocol-document-caps.json) holds the
  reviewed protocol document caps.
- [`../scripts/verification/dependency-audit.mjs`](../scripts/verification/dependency-audit.mjs)
  runs strict and baseline audits. The scheduled workflow uses
  [`dependency-audit-pr.mjs`](../scripts/verification/dependency-audit-pr.mjs)
  to maintain the update pull request and preserve human commits.
