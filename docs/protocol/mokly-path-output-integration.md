## Generated And Delivered Paths

`mockupsDir` remains the authored catalogue root. Its sole owned child is
`mokly-generated/`. Generated-relative names are:

| Content                          | Path inside `mokly-generated/`                 |
| -------------------------------- | ---------------------------------------------- |
| Page or light Markdown document  | `<entry path>/index.html`                      |
| Dark Markdown document           | `<entry path>/index.dark.html`                 |
| Screen or component variant view | `<entry path>/index.<viewport>[.dark].html`    |
| Compiled root CSS                | `styles/<repository-relative root module>.css` |
| Copied imported CSS asset        | `assets/<repository-relative asset>`           |
| Copied Markdown resource         | Its validated document-resource route          |
| Private manifest                 | `mokly-manifest.json`                          |

Use cases and component parents have no generated document; their shell routes
remain navigable. Public current bytes are under
`/static/mokly-generated/<generated-relative path>`. Authored closure files
remain at `/static/<catalogue-relative path>`. The manifest is never public.
Shell URLs use `/view/<entry path>/`, with the incoming accepted `/index.html`
and trailing-slash normalization. No kind prefix is added to entry identity.

Keep the existing `styles`/`assets` first-segment reservation for generated HTML,
case-insensitively, before rendering. The exact `build-invalid` detail remains
`generated HTML route uses reserved first segment <segment>: <route>; styles and assets are reserved for generated stylesheets and assets`.
The incoming path grammar also reserves `mokly-generated` as a first entry
segment. These are fixed output namespaces, not blanket bans on authored names.
Generated and authored routes remain separate namespaces, even with identical
suffixes. Apply ordinary file/directory and case-folded collision checks across
all generated documents, CSS and copied resource routes.

`GENERATED_DIRECTORY` and `VIEWER_DIRECTORY` keep their single definitions.
All new document, move, preview, navigation and comparison endpoints use
`mokly-viewer/`; no `__mokly/` or `__generations/` alias returns. Exported shells
live at `view/<entry path>/index.html`. Comparison files live at
`mokly-viewer/diffs/generations/<digest>/`, with both snapshot sides containing
`mokly-generated/` for generated bytes and catalogue-relative authored closure
paths beside it. Derive every path with the shared helpers.

## Markdown Resources And Public Closure

Retain the incoming allowed Markdown media/PDF types and root confinement.
Resolve each resource from its source Markdown file, retain its original path
in private `sourceFiles` and the document's `resources`, and copy exact bytes
to its validated generated-relative route. The original input remains private
and watched as source. Its generated copy belongs in `generatedFiles`, not
`assetClosure`. An asset imported by both CSS and a document retains each
required generated route, with normal collision and byte consistency checks.

All generated Markdown HTML and copied resources participate in the same
pending-generation validation as screens, pages and imported styles. Use the
[shared closure builder](./mokly-public-closure.md) for public references,
including PDF links and authored HTML. A generated copy may be public even
though its source is protected. Never authorize the source path to avoid a
copy. On demand, validate the selected document and its resource closure without
rendering unrelated generated navigation targets.

Changes compares copied resource bytes and retained Markdown source bodies
through the incoming move/evidence rules. Source bodies remain private even
when needed for similarity. Keep per-view move resource aliases for comparison
only; they do not redirect Serve or published snapshots.

## Writers And Accepted Generations

Only `build`, `build --watch` and the `serve --build` parent write and take the
output writer lock. One lock covers whole-tree validation, staging, replacement,
rollback and cleanup. Plain Serve, export, publication, compilation and Check
never acquire or wait for that lock. Untracked Check ignores disk output;
tracked Check still checks its safe complete tree after index classification.

Accepted generations keep the [immutable checked route set](./mokly-generation-routes.md).
Workers reject routes outside it. Build it from accepted in-memory inputs and
outputs, never by scanning an output directory. Remove mixed-layout collision
scans and ownership-based orphan discovery; whole-tree replacement owns every
generated file. Retain source confinement, actual generated collisions and
current writer lock guarantees. A stale or symlinked ignored output tree cannot
block compilation, untracked Check or nonwriting delivery.

No ownership header grants access, deletion or replacement. Keep only the plain
generated notice. No output modes, transformer, legacy export adoption, earlier
manifest filenames or earlier-format content readers return during integration.
Export keeps current ownership v3 and its named refusal errors. Package-root
equality remains an export-only `export-invalid` check.

## Baselines And Required Smoke

Manifest v9 is the only readable content format. The generated subtree, exact
inventory and blob hashes still select per-commit Git blobs or the base's own
rebuild. A committed root-level manifest never decides selection. After the
base's own recipe, a recognized pre-v9 manifest at its canonical generated or
root-level location produces `baseline-incompatible-earlier`, with no content
read and no cached incompatible entry. Keep partial-cache cleanup, valid
settings-mismatch failure and the current moved-root discovery boundary.

Serve keeps All usable. Export and Changes-enabled publication succeed with
`changesStatus: "unavailable"`, null comparison URL and no historical content.
Use the exact product line:

```text
Changes are unavailable because the comparison base was built with an earlier version of Mokly. Changes will return once the base includes this version.
```

Run `npm run preview:build -- --include-changes --base origin/main` against the
pinned incoming main commit. Its own code writes its v8 layout; the combined
package must detect that after rebuilding and finish the preview with the line
above and unavailable Changes. Do not inject the combined package into that
historical build or cache the earlier-format result.

Smoke Build, tracked/untracked Check, Serve and static export with Markdown,
folders and a moved entry. Use a separate v9 baseline to prove moved comparisons
and resources work. Check current-only delivery against the incoming v8 base,
all format rejection boundaries, namespace paths, lock-free nonwriters and
worker route rejection. Keep all unrelated incoming tests and assertions.
