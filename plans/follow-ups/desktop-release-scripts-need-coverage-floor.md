# Desktop release scripts need a coverage floor

- **Severity:** Medium. **Effort:** Large. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-24, the wider fix of review findings 4, 9 and 13 of the branch `calummoore/desktop-releases-become-latest-releases-clkn`.
- **Location:** `packages/desktop/package.json`, the `test:logic` script. `packages/desktop/scripts/*.mjs`.
- **Reason:** The fix adds a new gate, which the always-on rules reserve for the owner.
- **Category:** Test.

- **Terms:**
  - **Release scripts:** The Node scripts under `packages/desktop/scripts/` that build, publish and promote a desktop release. Only a real release runs them in full.
  - **Coverage floor:** A test run that fails when a line of the named files runs in no test.
- **Background:**
  - Three review findings of one branch were the same class: a release command path that no test ran.
    - Finding 4: the promotion command's manifest input.
    - Finding 9: the platform manifest producer.
    - Finding 13: the `release-publish` command and its hash comparison.
  - Each was found by a review, not by the gate. The `testing` skill rule "test at the boundary where data is serialized" was in force each time.
  - Node 24 has built-in test coverage, so a floor needs no new dependency.
  - A coverage run on 2026-11-24 showed that no test ran the publish command lines of `package.mjs`.
  - `plans/follow-ups/desktop-publish-command-has-no-test.md` holds the direct fix of finding 13.
- **Problem:** Nothing stops a new release script path that no test runs.
- **Impact if no action:** A defect in a release path shows first in a real release, after files are on the draft.
- **Root question:** How does the gate catch a release script path that no test runs?
- **Options:**
  - **A.** Keep the `testing` skill rule and the review as the only guard. Effort: Small.
  - **B.** Add a line-coverage floor of 100 percent for `packages/desktop/scripts/release-*.mjs` and the release modes of `package.mjs` to the desktop logic tests, with marked exclusions for code that only CI can run. The command tests then pass `NODE_V8_COVERAGE` to their child processes. About ten small error branches need a test or an exclusion. Effort: Large.
  - **C.** Add the floor at a lower level, such as 90 percent, so that the small error branches need no work now. Effort: Medium.
- **Left out:** A mutation-testing gate needs a new dependency and runs much longer. It catches weak assertions, which is a different class.
- **Wider fix:** B.
- **Previous examples:** Findings 4, 9 and 13 of the same branch.
- **Recommendation:** B. Release paths run only in real releases, so a missed path costs a version. A floor stops the class at the gate.
- **Action:** ask the user, because B and C add a new gate.
