# Repository step loses its answers through settings

- **Severity:** Medium. **Likelihood:** Common. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-27, from the branch `calummoore/multiple-org-configuration-error-9mms`, review finding 4 of round 2.
- **Location:** `packages/app/src/screens/account/repository-field.tsx:24-39` (`ManageAccess`), `packages/app/src/screens/account/choose-repository-screen.tsx:126-133` (the step's answers and its repositories read), `packages/app/src/screens/account/repository-project.ts:38` (`useRepositoryProject`, which holds the slug), `packages/app/src/data/use-slug-suggestion.ts:126-127`, `packages/app/src/settings/dialog-host.tsx:196-215` (the phone handoff), `packages/app/src/settings/panes/github-pane.tsx:190-197` (**Add GitHub account**), `packages/app/app/_layout.tsx:28`, and `docs/protocol/cloud/product-accounts-and-roles.md:79-96` (the repository step).
- **Reason:** Each option that meets the goal adds a rule for keeping a form's unsaved answers, which no requirement covers, and the options trade the answers' lifetime against what lands in the address.

- **Terms:**
  - **Repository step:** The Mokly Cloud form at `/:workspace/-/new` where a person chooses a GitHub repository, a config path and a project slug for a new project.
  - **Manage repository access:** The link under the repository field. Since 2026-11-27 it always opens the GitHub accounts pane.
  - **GitHub accounts pane:** The `github` pane of the settings dialog. On a desktop it opens as a dialog over the page at `?settings=github`. On a phone it is its own route, `/:workspace/-/settings/github`.
  - **Add GitHub account:** The pane's action for owners and admins. In a browser tab it sends the whole tab to GitHub to install the App on another account, and GitHub returns to the pane route in a new page load. The desktop shell opens GitHub beside its window instead (`github-pane.tsx:165-168` and `:212-219`).
- **Background:** The step keeps its answers in component state: the chosen repository ID, the config path (default `mokly.config.json`) and the slug, which `useSuggestedSlug` suggests from the repository. The root layout draws one route at a time (`_layout.tsx:28`). Before 2026-11-27, a workspace with one GitHub account had a link that opened GitHub in a new tab, so the step stayed open. On 2026-11-27 the user chose that the link always opens the pane, because only the pane can add a second organization.
- **Problem:** On a phone, the dialog host replaces the step with the pane route, so the step unmounts, and Back mounts it again with no repository, `mokly.config.json` and a new suggested slug. In a browser tab, on a desktop or a phone, **Add GitHub account** leaves the page and returns to the pane in a new page load, so the answers are gone there too. A step that stays open does not read its repositories again after a change on GitHub in another tab, so a new grant shows only after a reload, which also clears the answers.
- **Screenshot:** None, because the loss needs a phone-size walk with a filled form and a database, and the code shows it: the step's answers are component state that the route change unmounts.
- **Impact if no action:** A person who checks access or adds an account after filling the form must fill it again. This now also hits one-account workspaces on a phone, which kept the form before 2026-11-27.
- **Root question:** How does a person who leaves the repository step through **Manage repository access** come back to it, on any surface, with their answers and with a list that shows the access they changed?
- **Options:**
  - **A.** Open the pane in a new tab on a phone, and read the repositories again when the tab regains focus. The step stays open, but a phone gets a second tab, and the add-account trip still clears the answers. Effort: Medium.
  - **B.** Keep the step's unsaved answers in app memory for the workspace and the history entry, restore them on return and clear them on create. It covers the phone route only through the browser's Back: the full-screen layer's own exits go to `/settings` and `/dashboard` (`packages/app/src/settings/layer-screen.tsx:144` and `:241-243`), which open the step in a new history entry. It does not cover the add-account trip, which starts a new page load. Effort: Medium.
  - **C.** Keep the step's unsaved answers in `sessionStorage`, keyed by the workspace ID: the repository ID, the config path and a slug that the person typed. Restore them when the step mounts and forget them when the project is created. The step reads its list on mount, and `chosenRepository` ignores a restored repository that the list no longer has. It covers the phone route, the add-account trip on every surface, and a reload. It needs a typed start value for the slug in `useRepositoryProject` and `useSuggestedSlug`, a round trip in `packages/app/src/_tests_/two-accounts-mobile.spec.ts:23-43` (which already follows the link to the phone route), an add-account check beside `packages/app/src/_tests_/two-accounts.spec.ts:184` (which checks that the desktop close keeps the answers), and one rule in `product-accounts-and-roles.md`. The answers can come back on a later visit in the same tab. Effort: Medium.
  - **D.** Write the answers to the step's own query keys with replace, and carry them in the add-account `returnTo`. The person's free text goes into the address and each history entry, the step needs an address grammar in the protocol, and the full-screen layer's back to `/settings` drops the keys. Effort: Medium.
  - **E.** Give full-screen settings a layout that keeps the page beneath mounted until the person returns. It covers only the phone route, keeps a stale list, and breaks the one-route-at-a-time rule that `packages/app/src/navigation/leave-page.ts:18-23` and `packages/app/src/settings/layer-address.ts:40-48` rely on. Effort: Large.
  - **F.** Build one draft record per tab for all product forms, on the pattern of the settings drafts in `packages/app/src/settings/drafts.ts`, stored in `sessionStorage` and keyed by form and subject. Add one rule to `docs/protocol/cloud/web-product-shell.md`: a product form keeps its unsaved answers through each trip that its own links start, and forgets them when it submits. The repository step and the CLI form use it first. Effort: Large.
- **Left out:**
  - The direct link to GitHub. It breaks the decision of 2026-11-27.
  - A confirmation before the link leaves a form with answers. The person still cannot get the answers back.
  - Opening **Add GitHub account** beside the tab, as the desktop shell does (`github-pane.tsx:212-220`). Alone it fails on a phone, where the route change unmounts the step first.
- **Wider fix:** F. It keeps each product form's answers however the page is left.
- **Previous examples:** Commit `5a9f08007` kept the step and the viewer mounted when a panel closes on a desktop, and deleted the item `settings-close-resets-repository-step.md`, the desktop form of this problem. On a phone, settings from the viewer still remount it (`plans/follow-ups/phone-settings-remounts-viewer.md`).
- **Related:**
  - `plans/follow-ups/members-lack-github-manage-link.md`, the same link: its option G sends a member's link to GitHub when the workspace has one account, which would spare that member this trip. Neither item waits for the other.
  - `plans/follow-ups/account-shell-remounts-drop-focus.md`, the same file `packages/app/app/_layout.tsx`: its option C adds a route layout, and option E here adds another, so one branch should design both.
  - `plans/follow-ups/phone-settings-remounts-viewer.md`, the same phone handoff: option E would also fix that item.
  - `plans/follow-ups/settings-close-loses-redrawn-opener.md`, the same step: under E, the phone return also needs that item's focus return.
- **Recommendation:** C. The add-account trip is why the link opens the pane, and that trip starts a new page load, so only storage that outlives the page keeps the answers through it. F best protects the codebase, but it is Large and reaches every product form, so C fixes this step first and F can follow on the same record.
- **Action:** ask the user, because C adds a rule for keeping a form's unsaved answers that no requirement covers.
