# Viewer More rows miss the required size

- **Severity:** Medium. **Likelihood:** Common. **Effort:** Large. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-03, from the hosted viewer layout verification on `conductor/follow-ups-hosted-viewer-layout`.
- **Location:** `packages/app/src/screens/viewer/more-menu.tsx`, `packages/app/src/viewer/menu-list.tsx`, `docs/mockups/styles/product/viewer-canvas-menu.css`, `packages/app/src/settings/row-menu.tsx`, `packages/app/src/screens/account/connect-screen.tsx`, and the Viewer top bar paragraph of `docs/protocol/cloud/folio-viewer.md`.
- **Reason:** The recommended shared-control fix needs another repository and a release, while local alternatives change the design or requirements.
- **Category:** Product bug.
- **Terms:**
  - **More menu:** The viewer's compact cloud action menu. Its rows are the cloud's own, drawn in `@firna/ui`'s menu row metrics, because `@firna/ui` menu rows take no link.
  - **Touch target:** The clickable area of one menu row, measured in CSS pixels.
  - **Touch viewport:** A window below 768 px, where `useCompact()` selects touch sizing. Wider windows keep pointer density.
- **Background:** The compact viewer groups its cloud actions under More. More holds the project, History and Share, a divider, then the account rows: who is signed in, Theme, Settings, Docs, Changelog and Sign out. Settings is an account row, because the bar has no Settings button. The cloud draws More's rows itself, and `docs/mockups/styles/product/viewer-canvas-menu.css` gives them `@firna/ui`'s menu row metrics. On a pointer viewport More opens as `Popover` from `@firna/ui/popover`. On a touch viewport it opens as the registered panel's bottom sheet, where each row is at least 44 px high. The More and Menus sections of `docs/protocol/cloud/viewer-chrome-account.md` and the Account menu paragraph of `docs/protocol/cloud/folio-viewer.md` hold these rules. They date from the user's decision of 2026-11-19 that Theme and Settings move into an account menu that the reader's avatar opens. The Viewer top bar paragraph of `folio-viewer.md` also gives every grouped action a 44 px target, without a viewport limit. `docs/protocol/cloud/folio-chrome.md` and `docs/protocol/cloud/shared-control-registrations.md` require 44 px targets on touch viewports. More also appears in narrow pointer windows. The settings row menu and the workspace selector still draw the rows of exact-pinned `@firna/ui` 4.0.0.
- **Problem:** At 390 px, More's sheet rows each measure 44 px. At 768 and 1000 px, More's popover rows each measure 34 px: 8 px of padding above and below an 18 px line, the metrics that the cloud copies from Firna. The pointer rows conflict with the unqualified More sentence, while their triggers keep pointer density. The settings row menu's sheet and the workspace selector still draw Firna's single-line rows, which break the mobile target rule on a phone. Firna fixes vertical padding at 8 px and the label line at 18 px. Its public row props and theme expose no row-height setting.
- **Impact if no action:** Single-line phone actions remain harder to tap than the required 44 px targets. The More requirement remains unclear for pointer windows.
- **Root question:** How does each grouped action get the target size that its viewport requires?
- **Options:** Milestone 13 already gave More's phone rows 44 px targets, in the registered panel's bottom sheet, which the earlier options B and G asked for. Two parts stay open: More's 34 px rows in a narrow pointer window, and the single-line Firna rows of the settings row menu and the workspace selector on a phone.
  - **A.** Accept 34 px rows for the settings row menu and the workspace selector on a phone. Change `folio-viewer.md`, `folio-chrome.md` and `shared-control-registrations.md`. Effort: Small.
  - **B.** Compose the settings row menu and the workspace selector from cloud-drawn rows with 44 px targets on touch viewports, as More now does. The host owns the active row and focus movement. Update the menu surface rules in `shared-controls.md` and their drawings. Effort: Medium.
  - **C.** Add a public row-minimum option to Firna, release it, and deliberately bump the three pinned workspaces in a separate change. Apply it to the settings row menu and the workspace selector on touch viewports. Effort: Medium.
  - **D.** Add visible Firna `DropdownIconBox` tiles through the public `leading` slot of those two families on touch viewports. A row then measures 8 + 28 + 8 = 44 px. This needs new drawings and changes to the icon-size and tinted-fill rules in `folio-chrome.md`. Its sizing depends on the current tile and padding dimensions. Effort: Medium.
  - **E.** Clarify that the Viewer top bar paragraph's 44 px floor for More's grouped actions applies only on touch viewports, so More's pointer popover keeps its 34 px rows. E settles More alone. Combine it with A, B, C, D or F for the two other families. Effort: Small.
  - **F.** Give every Firna dropdown row family one supported floor, then release it and bump the pin in `packages/app`, `apps/mockups` and `packages/tokens`. Apply 44 px on touch viewports through one shared helper in the settings row menu, the workspace selector and their drawings, with E's viewport clarification. A release that also gives menu rows a link, as [the link row item](./menu-rows-take-no-link.md) asks, lets More return to Firna's rows. This needs two repositories and all affected call sites. Effort: Large.
- **Left out:** Ad hoc CSS overrides break the shared-control rule. A global breakpoint change does not change the fixed dropdown padding. Empty sizing spacers break `shared-controls.md`'s rule that public size and touch-target props set control geometry. Repeated secondary text breaks the product copy rule that supporting text stays optional. Firna `ResponsiveMenu` uses the same short rows. Changing nothing leaves the phone requirement unmet for the two families. The earlier option G, More in a sheet with 48 px rows, is left out, because More's touch sheet now has 44 px rows.
- **Wider fix:** F. One supported row floor covers all affected menu families and their drawings.
- **Previous examples:** The settings sheet in `packages/app/src/settings/row-menu.tsx` and the workspace selector in `packages/app/src/screens/account/connect-screen.tsx` use the same single-line rows. Their drawings use `docs/mockups/src/components/responsive-menu.tsx` and `options-list.tsx`. These additional cases follow from the shared implementation, rather than a browser measurement. More's own rows, `packages/app/src/viewer/menu-list.tsx`, show the cloud-drawn rows of option B.
- **Related:** [menu-rows-take-no-link.md](./menu-rows-take-no-link.md): a Firna release for its option B can carry this item's row floor.
- **Recommendation:** E with F. E settles More's pointer rows with one sentence, and F meets the mobile target rule for both remaining families with shared menu behavior. B is the strongest option that needs no Firna release.
- **Action:** ask the user, because F needs another repository and a release, while the local alternatives change requirements or menu design. The primary orchestrator had these options rewritten for the state after Milestone 13 on 2026-11-23.

Reproduce with a signed-in published project. At 768 px or 1000 px, open More and measure the elements with `role="menuitem"`: each measures 34 px. At 390 px, More's sheet rows each measure 44 px. Measure row boxes, not the 18 px text labels. A future fix must preserve every action, keyboard navigation, focus return, and the bar handoff.
