# Stage stacking test fails on new Chrome

- **Severity:** Low. **Effort:** Small. **Confidence:** Medium. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-20, from a local complete gate run on the branch `calummoore/fu-cloud-parent-usage-lists-xb6e` (PR #395).
- **Location:** `tests/browser/stage_stacking.spec.ts:19`, the narrow-stage rule in `packages/ui/src/stage/stage.css:30-37`, and the browser channel default in `playwright.config.ts:21`.
- **Reason:** CI runs the pinned Playwright Chromium, which passes, so the failure shows only in local runs with a newer system Chrome.

- **Source:** Implementation.
- **Category:** Test.
- **Terms:**
  - **Stage:** the `.mbk-stage` area of the Browse shell that holds the preview frames.
  - **Browser channel:** the browser that Playwright starts. `playwright.config.ts` uses `process.env["PLAYWRIGHT_CHANNEL"] ?? "chrome"`, so a local run uses the installed Google Chrome. CI sets `PLAYWRIGHT_CHANNEL: chromium`, the Chromium build that `@playwright/test` 1.61.1 pins.
- **Background:**
  - The test "stacked frames on a narrow stage start at its top so the first frame stays reachable" opens `/view/example/screens/welcome/` at 390 by 844 pixels.
  - It checks that the stage's `scrollTop` is 0, that the Mobile frame label is not above the stage, and then `toHaveCSS("justify-content", "flex-start")` on the stage.
  - Below 760 pixels, `stage.css` sets `flex-direction: column` and `justify-content: flex-start`, so that a column taller than the stage does not push its first frame above the scroll origin. Wider stages use `justify-content: safe center`.
  - On 2026-11-20, a local complete gate run on Chrome 158 failed at line 19: the computed `justify-content` was `flow-start`, not `flex-start`. A rerun on Chromium 149 passed 1 of 1.
  - Nobody has checked why Chrome 158 serializes the value in this way.
- **Problem:** The test checks the serialized keyword of the alignment, not the layout that the rule protects. A Chrome version that writes the same alignment with another keyword fails the test.
- **Impact if no action:** Every local gate run on a current Chrome fails this browser test. CI fails in the same way when a Playwright update brings a newer Chromium.
- **Root question:** How does the test prove that stacked frames start at the top of a narrow stage on every Chrome version?
- **Options:**
  - **A.** Replace the keyword check with a layout check of the same rule: the first frame starts at the top of the stage's content box, which start alignment gives and centring does not. Confirm first on Chrome 158 that the page itself still starts at the top. Effort: Small.
  - **B.** Accept both `flex-start` and `flow-start`, after a check on Chrome 158 shows that it writes the same declared value as `flow-start`. Effort: Small.
  - **C.** Make local runs use the pinned Playwright Chromium by default, as CI does. It changes the local browser of every browser test, so it needs its own decision. Effort: Medium.
- **Left out:** Delete the keyword check. The two other checks pass also when a short column is centred, so the rule would lose its test.
- **Wider fix:** None found. Search the browser specs for other `toHaveCSS` checks of alignment keywords when you apply A.
- **Previous examples:** None found.
- **Recommendation:** A. It tests the layout that the rule exists for, so a new keyword cannot fail it, and it keeps the protection.
- **Action:** fix after merge, apply A, because CI's pinned Chromium passes and the change keeps the protection of the rule.
