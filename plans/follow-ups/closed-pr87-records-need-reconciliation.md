- **Background:** The seed creates the seed token at step 8 of the seed steps in `docs/protocol/cloud/preview-seed.md`, uploads the catalogue, then revokes the token at step 11. That doc says that once the token exists, the seed always revokes it, also after a failure. The Job template sets `activeDeadlineSeconds: 1200`. ### `site-cleanup-page-size-refused.md`: Site cleanup never deletes closed PR previews

- **At capture:** Severity Low, Likelihood Common, Effort Small, Confidence High, Harder later No. Kind Outside the scope. Category Product bug. Added 2026-11-01, from the close of PR #84, on the branch `calummoore/preview-environment-creation-test`. Reason at capture: the branch that found it only recorded follow-up items, and the fix changes the site workflow and its cleanup script.
- **Checked:** 2026-11-01, at `206a581d`. The script still asks for 100 deployments a page. A fresh check found the refusal on all 78 close comments that the close job updated, and found all 83 closed PRs still served.
- **Location:** `scripts/cloud/site/cleanup.sh:29`, `:43` and `:62`, `.github/workflows/site.yml:6`, `apps/site/tests/site_cleanup.test.ts:61`, `docs/protocol/cloud/site-deployment.md` (the close rules).
- **Terms:** A site preview is the Cloudflare Pages deployment of the marketing site for one pull request, served at `https://pr-N.mokly-site.pages.dev`.
- **Background:** When a same-repository pull request closes, `.github/workflows/site.yml` runs `scripts/cloud/site/cleanup.sh` on the `pull_request` event. The script lists the deployments of the Pages project page by page, and deletes the deployments whose branch is `pr-N`. `docs/protocol/cloud/site-deployment.md` requires this deletion after a list of every page. A failure while listing reports the deployments as retained and deletes nothing. A refused list writes the status only to the PR comment and exits 0, with no log line or warning. A failed delete prints a warning.
- **The refusal:** The script has asked for `per_page=100` since its first commit, `6a27c76b` of 2026-09-17. The test double in `apps/site/tests/site_cleanup.test.ts` accepts 100. Cloudflare answers that list with HTTP 400: ``Invalid list options provided. Review the `page` or `per_page` parameter.`` A Cloudflare engineer wrote in Cloudflare Community thread 575193, in October 2023, that this list accepts at most 25 a page. PRs 17, 37, 38, 39 and 53 got no Site run at their close. GitHub starts no `pull_request` run for a PR with a merge conflict, and PR 53 still shows one.
- **Problem:** Cloudflare refuses the list of 100 a page, so the cleanup deletes nothing on any close. A close that starts no run, as with a merge conflict, gets no cleanup at all.
- **Impact if no action:** No closed pull request loses its site preview. On 2026-11-01, all 83 closed PRs served their preview with HTTP 200, and every close since PR 1 ran green with the refusal hidden in its comment.
- **Root question:** How does every closed pull request lose its site preview, also when its close run fails or does not run?
- **Options:**
  - **A.** Leave out `per_page`, so that Cloudflare uses its default page size. End the loop on `result_info.total_pages`, or on an empty page when the count is absent. Make the test double refuse more than 25 a page, as Cloudflare does. Cost: more list requests for a large project. Effort: Small.
  - **B.** Ask for `per_page=25`, and end the loop when a page has fewer than 25. Cost: a lower limit at Cloudflare breaks the cleanup again. Effort: Small.
  - **C.** Change nothing, and remove old previews by hand in the Cloudflare dashboard. Cost: previews stay until someone removes them, and the comments keep saying `retained`. Effort: Small.
  - **D.** Fail the close job after the comment step when the cleanup status starts with `retained`. Cost: a short Cloudflare outage also turns the run red. It is a new failing check, so it needs the user. Effort: Small.
  - **E.** A, and run the close job on `pull_request_target` with the `closed` type, as the Preview workflow does. GitHub starts that event also for a PR with a merge conflict, and its default checkout runs no PR code. Cost: a job that holds the Pages secret on this event needs a security review. Effort: Small.
  - **F.** A, then remove the previews of the 83 closed PRs once, with the fixed script. Cost: a temporary manual trigger, or a run with the user's Pages token. Effort: Small.
  - **G.** A, and a daily and manual sweep job. It lists the preview deployments, reads the open PRs from GitHub, and deletes each `pr-N` deployment whose PR is not open. A failed sweep fails its run. Its first run removes the kept previews. Cost: a new trigger, a new requirement in `docs/protocol/cloud/site-deployment.md`, and a new failing run, which need the user. Effort: Medium.
  - **H.** Move the Pages branch cleanup into one shared, tested action that mokly-cloud, mokly and futex-ai/ui pin. Cost: a new shared home across two GitHub organizations, with its own tests and releases. Effort: Large.
  - **I.** Deploy each PR to its own Pages project, and delete the project on close. Cost: a new preview URL in the protocol and the comment, and a project for each PR. Effort: Large.
  - **J.** A, and print a workflow warning when the cleanup status starts with `retained`. The run stays green, but its summary shows the failure. Cost: the warning does not help a close that starts no run. Effort: Small.
- **Left out:** A list filtered by branch: the deployments list takes only `env`, `page` and `per_page`. A public check of the closed-PR aliases: it reports a served preview but removes none. A record of each deployment id at deploy time: a newer push can cancel the run after the upload, and the list of A still finds that deployment.
- **Wider fix:** G. It removes the preview of each closed PR, whatever made its close fail or not run, and its failing run shows a refusal that stays. **Previous examples:** The catalogue preview cleanup of the open-source `mokly` repository asks for `per_page=100` in its `.github/workflows/preview.yml`, and its closes of PRs 224 to 258 report the same refusal. The Storybook previews of `futex-ai/ui` failed the same way on PRs 98 to 106, closed on 2026-07-20.
- **Proposal at capture:** Recommendation J. It restores the cleanup and makes the next refusal visible, and no rule blocks it. G is the wider fix, and it needs the user. Action: fix after merge, apply J, because the branch that found it changes only follow-up items. D, E and G need the user: D and G add failing runs, and E needs a security review.
