# Private preview sample project needs log access

- **Severity:** Medium. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-19, from the branch `calummoore/combine-mokly-cloud-into-repo-704s`, review finding 201: the new option D of its check.
- **Location:** `crates/mkc-api/src/preview_seed/identity_validation.rs:55`, `crates/mkc-api/src/preview_seed/identity.rs`, `crates/mkc-api/src/preview_seed/_tests_/service/fixtures.rs:57`, `crates/mkc-api/tests/preview_seed/`, `infra/scripts/preview-comment.py:94-100`, `docs/protocol/cloud/preview-seed.md`, sections "Account And Sign-In Link" and "Seed Steps", `docs/protocol/cloud/preview-seed-local.md`, section "Local Stack", `docs/ops/preview.md`, section "Review A Labelled PR", and `docs/development/cloud.md`, section "Local Preview Stack".
- **Reason:** A public sample project changes a requirement of the preview seed contract and what each preview shows, and no user decision covers that change.

- **Terms:**
  - **Sample project:** the project `Mokly Cloud`, slug `mokly`, repository `mokly-ai/mokly`, that the preview seed creates with the pull request's mockups. It is in the workspace `Mokly` (`mokly-ai`) of the shared preview account `preview@mokly.ai`.
  - **Open preview:** the link of the preview comment that signs in the shared account with the namespace secret. `infra/scripts/preview-comment.py:94-100` adds it only when the repository is private.
  - **Log reader:** `infra/scripts/preview-link.py`, which reads an email sign-in link from the API logs of one preview. It needs namespace pod and log access through `kubectl`.
  - **Private artifact limit:** the embedded viewer fetches comparison documents without credentials, so it cannot show the Changes of a private catalogue. `docs/protocol/cloud/viewer.md`, section "Private Artifact Limit", defines it.
- **Background:**
  - On 2026-11-17 Mokly Cloud moved into this public repository, `mokly-ai/mokly`. Its previews deploy one namespace for each pull request with the `preview` label.
  - The seed requires a private sample project. Step 6 of the section "Seed Steps" of `docs/protocol/cloud/preview-seed.md` states it, and `identity_validation.rs:55` checks it. PR previews set the preview plan to `team`, and Team makes new projects private by default. No document records why the sample project must be private.
  - A public repository gets no **Open preview** link, because anyone can read the comment. On 2026-11-19 `docs/ops/preview.md` gave reviewers this path: request a sign-in link for `preview@mokly.ai` on Sign in of the preview app, then read it with `MKC_DOMAIN=mokly.ai python3 infra/scripts/preview-link.py preview-pr-N --email preview@mokly.ai`. A reviewer without log access asks an operator to read the link.
  - Only the shared account can open the private sample project. Its Changes show an overlay without an action, because of the private artifact limit.
  - `docs/protocol/cloud/platform-model.md`, section "Projects And Visibility", says that public visibility grants anonymous project reads and publication reads. It never grants mutations or access to members and tokens. A change of a project to public does not need Team.
- **Problem:** A reviewer of this public repository needs cluster log access, or an operator, to open the sample project. The preview still cannot show the Changes of the pull request.
- **Impact if no action:** Each preview review needs an operator or a person with log access. Reviewers cannot check the Changes of a pull request in its preview.
- **Root question:** How can a reviewer of this public repository open the preview sample project and its Changes with the least access?
- **Options:**
  - **A.** Keep the private sample project and the email sign-in path of `docs/ops/preview.md`. Nothing changes. Effort: Small.
  - **B.** Add an operator command to `infra/scripts/preview-link.py` that prints the shared `/auth/preview/callback#secret=` link from the namespace Secret `preview-sign-in`. It needs Secret read access, so most reviewers still ask an operator. `docs/protocol/cloud/preview-scripts.md` has about 240 of its 250 lines. Effort: Small.
  - **C.** Make the sample project public in previews. The seed creates or changes the project to `public` and requires `public`. Anyone with the address then opens the sample project and its Changes without a sign-in. Update the seed contract, the local seed page, the runbook, the local stack guide, the seed tests, and `plans/follow-ups/seed-kept-rules-lost-tests.md`, whose option A uses a public project as its mismatch case. The sample project then no longer exercises a private catalogue in previews. Effort: Medium.
- **Left out:** A shared credential in the comment of a public repository breaks the rule that only a private repository's comment carries it. GitHub sign-in in previews breaks the rule that PR previews disable the GitHub App. Real email in previews needs a Postmark secret in each preview namespace, which previews do not have. A private repository reverses the move of the cloud into this public repository.
- **Wider fix:** None. This is one product choice for previews.
- **Previous examples:** None found.
- **Related:** `plans/follow-ups/seed-kept-rules-lost-tests.md`, same code: its project mismatch test uses a public project, so option C changes that test case.
- **Recommendation:** C. It removes the need for log access and shows the Changes, and the mockups of this public repository are public already.
- **Action:** ask the user, because the recommended option changes a requirement of the preview seed contract and what each preview shows, and no user decision covers that change.
