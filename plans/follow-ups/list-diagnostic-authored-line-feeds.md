# Authored line feeds split diagnostic lists

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Fix after merge.
- **Added:** 2026-11-20, from finding 1 of the post-push review of branch `calummoore/fu-base-diagnostic-location-lines-udeb`.
- **Location:** `crates/mokly-cli/src/changes_output.rs:113`, `crates/mokly-cli/src/build_output.rs:172`, `crates/mokly-cli/src/redaction.rs:44`, `crates/mokly-catalogue/src/identity.rs:136` and `:244`, `packages/mokly/src/sidecar/describe.ts:95`, and `packages/mokly/src/sidecar/definition-shapes.ts:36`.
- **Reason:** This rare input needs producer changes beyond the base location-list fix. The fix does not become harder after that change merges.

- **Source:** Review.
- **Category:** Product bug.
- **Terms:**
  - **List diagnostic:** A catalogue message with one heading followed by indented source locations.
  - **Structural line feed:** A separator that a list builder adds between the heading and its locations.
- **Background:**
  - Head and base printers use `build_output::has_location_lines` for `DuplicateExport`, `DuplicatePath`, `CaseCollision`, `DuplicateFolder`, and `DuplicateMovedFrom`.
  - These messages pass through `Redactor::safe_lines`, which preserves every line feed and escapes other controls.
  - Native lists come from `identity::list`. It joins a heading and raw location strings into one message.
  - The sidecar builds `duplicate-export` text in `describe.ts`. It inserts `data.input.title` directly into the heading.
  - The sidecar requires a string title, but does not reject a line feed. Discovery also accepts file names that contain line feeds.
- **Problem:** The flat message does not distinguish structural line feeds from authored line feeds. A definition titled `First\nSecond`, exported by two entry modules, puts an extra physical line inside the heading. A line feed in a source path can add an apparent location.
- **Impact if no action:** A reader sees extra lines instead of visible `\u000a` escapes. Authored text can look like another location or diagnostic.
- **Root question:** How can head and base keep list separators while escaping each control character inside an authored value?
- **Options:**
  - **A.** Mark structural separators at the producers and carry their positions to both printers. Keep the raw message. This adds metadata to the sidecar diagnostic record. Effort: Medium.
  - **B.** Carry headings and location values separately through catalogue diagnostics. Escape each value before one shared renderer joins the lines. This retains the distinction by construction and can replace the code classifier. It changes the sidecar diagnostic record. Effort: Medium.
  - **C.** Escape controls in each authored part before the two list builders join their lines. Use the `\u{:04x}` form of `Redactor`. Update `identity::list` and the sidecar duplicate-export builder. Keep the current record and shared classifier. Add focused regression cases for an authored line feed at the two builders. Effort: Small.
- **Shared assumptions:**
  - Authored values with line feeds stay valid input. No option adds a rejection.
  - A list has one heading and one two-space-indented line per location. The exact-text tables and terminal contract require this.
  - Input without controls keeps its current terminal bytes.
  - C drops the assumption that only transported metadata can distinguish separators. Escaping before joining also keeps that distinction.
- **Left out:**
  - Escape every line feed: this breaks the required following location lines.
  - Infer separators from indentation: an authored title such as `Home\n  page` can use the same indentation.
  - Reject authored line feeds: this adds validation that no recorded decision permits.
  - Change nothing: the control-escaping defect remains.
- **Wider fix:** B. Separate values let one renderer own separators. A and B require a user decision before changing the record defined in `docs/protocol/mokly-sidecar-definitions.md`.
- **Previous examples:** Head errors already have the same issue through `Style::error_lines`. `git-uncommitted` avoids it by escaping each path before joining lines in `crates/mokly-cli/src/publish_errors.rs:138`.
- **Requirements:** `docs/protocol/mokly-terminal-errors.md:52` requires following location lines and control escaping per line. `docs/protocol/mokly-entry-modules.md:169`, `docs/protocol/mokly-paths.md:152`, and `docs/protocol/mokly-folders.md:190` define one heading followed by locations.
- **Compatibility:** C stores escaped values in `Issue.message` for every consumer, not only terminals. Trace those consumers before implementation. Keep their requirements. Rust and TypeScript need the same escape form. A future producer that bypasses these builders can repeat the defect. The new `ChangeDiagnostic.catalogue_code` field is internal: `mokly-cli` has `publish = false` and no other crate depends on it.
- **Cloud:** Cloud stores and displays these lines as log text. Its failure parser accepts only a leading `[mokly/{code}] ` line. Successful publication still follows its exit status and committed publication. No Cloud classification failure was established.
- **Related:** [serve-diagnostic-location-lines.md](./serve-diagnostic-location-lines.md) covers a separate printer that flattens list separators. This item makes the authored values safe before that printer preserves separators.
- **Recommendation:** C. It fixes the current builders without changing the sidecar record. B remains the stronger wider fix and needs a separate user decision.
- **Action:** fix after merge, apply C, because the input is rare and producer changes do not become harder after merge. This choice was made on 2026-11-20 after an independent finding check. The first pass recommended B.
