# Render writer tests wait forever on writer exit

- **Severity:** Low. **Effort:** Small. **Confidence:** High. **Harder later:** No.
- **Kind:** Outside the scope.
- **Added:** 2026-11-26, from the branch `calummoore/ci-speed-flaky-follow-ups-a-ube3`, the finding checks of review findings 1 and 9.
- **Location:** `crates/mokly-compare/src/_tests_/render_writer_tests.rs:88`, `crates/mokly-compare/src/_tests_/render_writer_startup_tests.rs:98`, `:101`, and `:118`, and `crates/mokly-compare/src/_tests_/render_writer_state_tests.rs:114`, `:124`, `:132`, and `:134`.
- **Reason:** All eight waits were already on `origin/main`, and the branch that found them fixed only the waits that it added.

- **Source:** Review.
- **Category:** Test.
- **Terms:**
  - **Writer thread:** the `mokly-documents` thread that `DocumentWriter::start` in `crates/mokly-compare/src/render_writer_control.rs` spawns. It saves rendered documents for reuse.
  - **Idle writer helper:** `IdleWriter` in `crates/mokly-compare/src/_tests_/idle_writer.rs`. Its writer thread owns a sender, so a test that waits on it fails at once when the thread cannot start or ends.
- **Background:**
  - Each wait below reads a channel whose sender lives in a test double that the store keeps: the backend mock, the image source mock inside the store's own `Startup`, the identity mock, or the observer mock. So the sender stays alive while the store lives, also after the writer thread ends.
  - The waits, with the stage at which the writer thread must end for the wait to hang:
    - `a_full_key_queue_returns_the_render_while_disk_publication_is_blocked`, `waiting.recv()` at line 88: the thread ends after its first idle signal and before it calls `save`. A spawn failure does not reach this wait. On 2026-11-26, a forced spawn failure, an impossible stack size on the writer thread, made this test fail at once in the idle writer helper.
    - `prepared_writer_reads_while_writes_wait_for_completed_changes`, `hashing.recv()` at line 98: the thread cannot start, or ends before it calls `digest`.
    - The same test, `bootstrapped.recv()` at line 101: the thread ends after `digest` and before it calls `initialize`.
    - The same test, `written.recv()` at line 118: the thread ends after the resume and before it calls `save`.
    - `delayed_contention_records_keep_complete_idle_state_at_the_highest_sequence`, `initialization_seen.recv()` at line 114, `active_seen.recv()` at line 124, `busy_seen.recv()` at line 132, and `completion_seen.recv()` at line 134: the thread cannot start, or ends before it reaches the observer or identity call that sends on each channel.
  - Only the spawn failure was probed. The other stages come from a read of the code.
  - `docs/protocol/ci-test-timing.md` makes the CI job timeout the hang guard of the Rust tests. nextest sets no slow timeout here.
- **Problem:** When the writer thread ends at one of these stages, the test waits until the CI job timeout and shows no cause.
- **Impact if no action:** A writer start failure or an early panic costs a whole CI job timeout and gives no failure text.
- **Root question:** How do these tests learn that the writer thread ended before it sent the signal that they wait for?
- **Options:**
  - **A.** Wait with `recv_timeout` and a long diagnostic limit, as `process_stop_tests.rs` does, and fail with a message. A real hang still takes the whole limit. Effort: Small.
  - **B.** Wait in a loop that also checks the idle writer helper's receiver, and fail when it disconnects. Effort: Small.
  - **C.** Move each sender out of the double that the store keeps, so that it drops with the writer thread. This changes how the doubles get their senders in three test files. Effort: Small.
- **Left out:** A retry or a sleep, because the testing rules forbid them.
- **Wider fix:** C. A sender that the writer thread owns ends every wait when the thread ends, as the idle writer helper already does.
- **Previous examples:** The idle writer helper fixed the same class for the first offer of two of these tests on 2026-11-26.
- **Recommendation:** C. It gives each wait an end signal from the thread itself, with no time limit.
- **Action:** fix after merge, apply C, because all eight waits predate the branch that found them.
