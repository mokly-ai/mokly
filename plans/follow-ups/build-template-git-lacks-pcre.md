# The template's default Git lacks PCRE

- **Severity:** Medium. **Likelihood:** Rare. **Effort:** Medium. **Confidence:** High. **Harder later:** No.
- **Kind:** Needs decision.
- **Added:** 2026-11-26, from the branch `calummoore/builds-give-the-template-a-git-that-9abx`, review finding 7 of round 2.
- **Location:** `infra/e2b/build/e2b.Dockerfile:20` to line 21, the `make ... install` of the Git source build; `docs/protocol/cloud/cloud-build-runner.md`, section "Template"; `docs/ops/build-template.md`, section "Release Prerequisites".
- **Reason:** Every fix except D needs a new E2B template release, and D changes a protocol requirement.

- **Source:** Review.
- **Category:** Product bug.
- **Terms:**
  - **Build template:** the E2B sandbox image, `mokly-build-v<N>`, in which Mokly Cloud runs the checkout, the install, and `mokly publish` of a customer repository.
  - **PCRE2:** the library behind Perl-compatible patterns in Git, such as `git grep -P`, `git log -P`, and `grep.patternType=perl`.
- **Background:**
  - Release `mokly-build-v5` (2026-11-26) builds Git 2.56.1 from source with `make prefix=/usr/local NO_TCLTK=1 NO_GETTEXT=1 NO_PERL=1 NO_PYTHON=1 NO_RUST=1 install`. It does not set `USE_LIBPCRE`, so that Git has no PCRE2.
  - Such a Git exits 128 on a real Perl pattern, for example `git grep -P 'Mokly(?= Cloud)'` gives `fatal: cannot use Perl-compatible regexes when not compiled with USE_LIBPCRE`. A plain-text `-P` pattern such as `git grep -P 'Mokly'` still works, so a check needs a real Perl pattern.
  - Debian's Git 2.39.5 is built with `USE_LIBPCRE2=1`, and it still sits at `/usr/bin/git` in v5. Ubuntu's Git 2.43.0 also supports `-P`.
  - The pinned `e2bdev/base` already holds `libpcre2-dev` 10.42. The runtime library `libpcre2-8-0` stays after any purge, because the essential package `grep` pre-depends on it. So v5 lacks only the build flag.
  - Mokly and the cloud runner never use Perl patterns in Git. Only customer code meets the gap: install lifecycle scripts, which `docs/protocol/cloud/cloud-build-runner.md` calls the consumer's build, and base-install scripts when the repository enables them.
  - The template contract in `docs/protocol/cloud/cloud-build-runner.md`, section "Template", promises "Git 2.43 or newer" and names no optional Git feature.
- **Problem:** The default Git of v5 cannot run Perl-compatible patterns, which the Git of earlier templates and of common Linux CI images can.
- **Impact if no action:** A customer script that uses `git grep -P`, `git log -P`, or `grep.patternType=perl` fails in cloud builds with exit 128, while it works in the customer's own CI.
- **Root question:** Must the template's default Git support Perl-compatible patterns for customer build scripts, and if so, how does the template supply them?
- **Options:**
  - **A.** In a new release, add `USE_LIBPCRE=1` to the Git build, name `libpcre2-dev` in the build install but not in the purge, and verify `git grep -P 'Mokly(?= Cloud)'`. Ship it in the release that fixes `plans/follow-ups/build-template-lost-its-compiler.md`, so the added cost is Small. Effort: Medium alone.
  - **B.** In a new release, ship a pinned Debian package built from the newer Git source with Debian's build options. Effort: Large.
  - **C.** Move to a pinned base whose packaged Git meets the floor, such as Debian 13's Git 2.47.3, which links PCRE2. This changes the `e2bdev/base` rule in `docs/protocol/cloud/cloud-build-runner.md`, `docs/protocol/cloud/repository-layout.md`, and the `e2b_base` check in `xtask/src/policy/build_pins.rs`. Effort: Large.
  - **D.** Keep v5, and state in the "Template" section that the template promises no optional Git feature, such as Perl-compatible patterns. Record the Git build options of v5 in the runbook. Effort: Small.
- **Left out:**
  - A runner `PATH` that finds `/usr/bin/git` first. It keeps the second Git that `plans/follow-ups/build-template-keeps-a-second-git.md` removes.
  - A probe check alone. It detects the gap only and fails the enabled v5. It belongs in the verification of A.
  - A third-party prebuilt Git. Git publishes no Linux binaries, so it adds a new supplier for one optional feature.
- **Wider fix:** C. A distribution-built Git keeps every optional feature of the distribution, and the base then supplies one Git.
- **Previous examples:** `mokly-build-v2` broke npm while `npm --version` still passed.
- **Related:** `plans/follow-ups/build-template-keeps-a-second-git.md` purges Debian Git, the only Git with PCRE2 in v5, so its option A must ship with A here. `plans/follow-ups/build-template-lost-its-compiler.md` needs the same release.
- **Recommendation:** A, in the release that fixes the compiler, because the base already has the library and only one flag is missing. D if no release is planned.
- **Action:** ask the user, because A, B, and C need a credentialed template release, and D changes the template contract.
