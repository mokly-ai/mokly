# Derived Mode In-Memory Output And The Generated Directory

## Summary

Two related changes to how Mokly handles generated output. Both follow the
same principle recorded by the user: Mokly must not create files the user did
not ask for, and generated content must never be mixed with authored content.

**Change 1: derived mode keeps Serve and export output in memory.** In the
default `generatedOutput: "derived"` mode, Serve's background completion,
watched Serve's candidate output, and every export write the current tree's
generated routes and `mokly-manifest.json` into the output directory as a side
effect. Nothing reads those files back in derived mode: `check` ignores them,
Serve renders on demand, and comparisons and exports take the head side from
the in-memory compilation. The writes are a leftover from committed mode, where
the working-tree copy must stay current. `mokly build` is unchanged in both
modes: a user who runs it is asking for files, and the baseline builder relies
on the historical commit's own `build` to harvest its output.

**Change 2: generated content lives alone in `.generated`.** Today
`mockupsDir` is both the generated output root and the public asset root, so
authored stylesheets sit beside generated HTML. That overlap is why ownership
headers, overwrite refusal, orphan and unclaimed detection, the ownership grep
in the derived index check, and per-file ignore rules exist. After this change
`mockupsDir` names the catalogue directory, Mokly owns exactly
`<mockupsDir>/.generated/`, and that directory is replaced wholesale on every
build. Authored assets stay in the catalogue directory, referenced by path as
today, and the build copies every referenced asset into `.generated/` so the
generated tree remains self-contained and portable. For the example:

```
examples/basic/.generated/         all generated files, replaced on every build
examples/basic/styles.css …        authored, tracked (13 stylesheets)
examples/basic/design-library/**   authored, tracked (15 stylesheets)
```

Decisions:

- `build` keeps its transactional write in both modes. In derived mode the
  result is a local snapshot for the user; it stays untracked and `check`
  keeps enforcing that.
- Serve (watched and `--no-watch`) and export, including publication, never
  write generated output in derived mode. In committed mode they keep writing
  so the working-tree copy stays current.
- No new flag, environment variable, or config option for change 1. The
  baseline builder and `review.baselineBuild` are unchanged except for the
  harvest path.
- `mockupsDir` keeps its name and becomes the catalogue directory. The
  generated child is the fixed name `.generated`, like `.mokly-cache`. A
  renaming of `mockupsDir` is out of scope.
- The public surface becomes the referenced asset closure: stylesheet rules,
  renderer resource records, and every local URL reachable from generated
  documents and their CSS. Closure files must be regular files under
  `mockupsDir`, outside `.generated`, and not protected source. The build
  copies each one into `.generated/` at the same `mockupsDir`-relative path,
  so generated hrefs are unchanged. Serve reads closure files live from their
  authored location; export ships the copies. `publicExclude`, hand-written
  public HTML under `mockupsDir`, and the directory-based public policy are
  removed. Pages are entries already.
- `.generated/` is disposable. A build stages the new tree and swaps it in;
  nothing inside is protected. Ownership headers stop carrying meaning; a
  one-line "Generated by mokly. Do not edit." marker remains for readers.
- Committed mode tracks all of `.generated/`, including the asset copies, and
  `check` compares the whole tree. Derived mode requires that nothing under
  `.generated/` or `.mokly-cache/` is tracked. Each mode needs one ignore rule
  at most.
- Moving the example's 28 tracked stylesheets out of `examples/basic/generated/`
  is authorized by the user's request for this layout.
- CSS imported from React components stays unsupported in this plan and is a
  follow-up; the closure model is designed so such imports can join it later.
- Backend and documentation only. No mockup or UI work.

copying, and migrates the example in one step, because generated hrefs only
resolve when both halves land together. After it, every command works with
the new layout and the example is the proof.

- [ ] Config (`src/config/types.ts`, `validate.ts`, `paths.ts`,
      `path_validation.ts`, `cache_paths.ts` or a sibling): add the
      `GENERATED_DIRECTORY` constant, resolve `config.generatedDir` as
      `<mockupsDir>/.generated`, reject entries, renderer, transformer, and

      directory.
- [ ] Output paths and compile (`src/build/output_paths.ts`, `compile.ts`,

## Post-merge follow-up (non-blocking)

- Make CSS imported from React components part of the asset closure: the
  module graph already records the import, so the build can copy the file
  into `.generated/`, emit the link, and attribute changes, instead of
  silently dropping it today.
- Smoke-test a fresh derived consumer with the next published package:
  `npx mokly` and `npx mokly export` produce nothing under `.generated/`,
  `npx mokly build` produces the self-contained tree, and a comparison against
  `origin/main` rebuilds its baseline from the new harvest path.
