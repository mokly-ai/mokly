# Styled Link Control Ancestor Rule

Replace the single fail-the-build rule for styled link controls
(`MockLink asChild`) with three tiers: structures that break the generated
document fail, structures that only degrade accessibility warn, and structures
that are harmless build silently. Give the build a warning channel to carry the
middle tier, name the offending element in every message, and state the
complete rule in the Links guide so it stays self-contained when the cloud
Reference page redirects there. The contract lives in the
[styled link controls protocol](../docs/protocol/mokly-link-controls.md); the
original delivery is recorded in
[MockLink Child Controls](./mocklink-child-controls.md).

## Background

`src/build/link_control_nodes.ts` uses one `isInteractive` predicate for the
control's descendants and for its ancestors, and every match fails the build
with `MockLink child control has an interactive ancestor` or
`contains another interactive control`. Headless Chrome shows the real risk is
narrower. A link inside another link is split by the HTML parser, so the
author's source and the generated bytes disagree, and a link inside editable
content cannot be activated. Every other ancestor case navigates normally; what
remains is invalid HTML, a second Tab stop, or ARIA hiding the link from
assistive technology. `<main tabIndex={-1}>`, `<details>` content, and group
roles such as `menubar` and `tablist` carry none of those problems, yet all
three fail today.

PR #42 shipped the descendant check and originally excluded `tabindex` from the
ancestor check. A Low-severity review item then rejected every ancestor
`tabindex` to match the specification wording rather than a demonstrated
hazard. The build has no non-fatal outcome: `compileCatalogue` returns a
manifest and outputs or throws. The CLI reporter can print a `!` warning line,
but nothing inside the build can ask it to. The Links guide states only the
descendant half of the rule, and the cloud repository plans to remove the
Reference page that carried the full rule.

## Decisions

### Tiers for ancestors of the control

| Tier    | Ancestors                                                                                                                                                                                                                                                                                 | Reason                                                                                   |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| error   | `a`, `area`; an editable element (`contenteditable` other than `false`); a nested child-mode link                                                                                                                                                                                         | The parser splits nested links; editable content swallows it                             |
| warning | `button`, `label`, `summary`, `object`; `audio`/`video` with `controls`; a `role` containing `button`, `link`, `checkbox`, `combobox`, `menuitem`, `menuitemcheckbox`, `menuitemradio`, `option`, `radio`, `searchbox`, `slider`, `spinbutton`, `switch`, `tab`, `textbox`, or `treeitem` | Two targets for one click or key press; children may be hidden from assistive technology |
| silent  | `tabindex` of any value; `details` content outside `summary`; `gridcell`, `listbox`, `menu`, `menubar`, `radiogroup`, `tablist`, `tree`, `treegrid`; every other element                                                                                                                  | Not a click target                                                                       |

### Tiers for descendants of the control

| Tier    | Descendants                                                                                                                                                                                                        | Reason                                                              |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| error   | `a`, `area`, `button`, `input`, `select`, `textarea`, `summary`, `details`, `label`, `iframe`, `object`, `embed`; editable elements; media with `controls`; the warning-tier ancestor roles; inline `on*` handlers | The nested control can take the click, or the link cannot be static |
| warning | `tabindex` on a descendant; the silent-tier ancestor roles                                                                                                                                                         | Extra focus stop or structural role inside a link                   |
| silent  | Every other element                                                                                                                                                                                                | Ordinary content                                                    |

The root contract is unchanged: one HTML `a`, `button`, `div`, or `span`, with
no role or `role="button"`/`role="link"`, not editable, no inline handlers, no
conflicting destination. Inactive-state propagation (`inert`, `aria-disabled`,
`aria-busy`, disabled `fieldset`) is unchanged. Mokly builds catalogues; it is
not an accessibility checker, so the warning tier explains the hazard and does
not block.

### Messages

One helper describes the offending element as `<tag>` or
`<tag attribute="value">`, where the attribute is the one that classified it
(`role`, `contenteditable`, `controls`, `tabindex`, or the `on*` name):

```text
<route>: MockLink child control is inside <a>; move the control outside it
<route>: MockLink child control is inside <button>; one click or key press has two targets
<route>: MockLink child control contains <input>; remove the nested interactive element
<route>: MockLink child control contains <span tabindex="-1">; the link has an extra focus stop
```

### Build warning channel

- A build diagnostic is `{ code, route, message }`. `code` is a stable
  kebab-case identifier (`link-control-ancestor`, `link-control-descendant`),
  `route` is the generated route, and `message` is the text above without the
  route prefix. Diagnostics are sorted by route then message and never appear
  in generated files, the manifest, or `check` comparisons.
- `adaptLinkControls` returns the adapted HTML plus its diagnostics.
  `transformCompatibilityDocuments` returns records plus diagnostics.
  `Compilation` gains `diagnostics`, so the background worker's structured
  clone already carries them to Serve. `CompiledDocument` carries the
  diagnostics of an on-demand document for parity, and Serve does not print
  them per request.
- Presentation follows the terminal-output contract. Plain mode writes one
  stderr line per diagnostic, `[mokly/warning] <route>: <message>`, and keeps
  stdout byte-identical; the plain contract gains this stderr exception. Rich
  mode writes `  ! <route>: <message>` after the rendering phase completes and
  before the summary, which is unchanged.
- `build`, `check`, `export`, and `publish` print the diagnostics of the
  compilation they write or validate. Secondary compilations (Changes
  evidence for derived output, the export freshness comparison) discard
  theirs. Serve prints each generation's diagnostics once, when the background
  catalogue completes, in watched and snapshot modes.
- `--strict` on `build`, `check`, `export`, and `publish` prints the warnings
  and then fails with `build-invalid` and the message
  `<n> build warnings with --strict`. Serve refuses the flag. Exit status stays
  `0` for warnings without `--strict`.
- The existing tests that assert `tabindex` ancestors and focus-only
  descendants fail are inverted on purpose. This is the only mainline behavior
  this plan removes.

## Milestone 3: Tiered link control rules

Split the shared predicate into the tiers above, produce warnings for the
middle tier, and name the offending element in every message.

- [ ] Add failing regressions in `tests/link_control_metadata.test.ts`: each
      silent ancestor (`tabindex` `0`, `3`, `-1`; `main tabindex="-1"`;
      `details` content; each group role) adapts with no diagnostics; each
      warning ancestor adapts with one diagnostic naming the element; each
      error ancestor fails naming the element; descendant `tabindex` and group
